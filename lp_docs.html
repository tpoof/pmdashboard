File map

Each Launchpad page is a LEAF report template published as report.php?a=lp_<name>. Shared behavior and styling live in two files under /launchpad/files/, so there is one copy of each to edit.

Launchpad files and what each one does
File Role
main.tpl Wraps every page. Loads the universal header and renders the page body inside <main id="body">.
leaf_header.js Universal header. Builds the nav, breadcrumb and mobile menu, runs the router, and hosts the modals and the Feedback button.
leaf_header.css Styles for everything the header script builds.
launchpad.css Design tokens (colors, radii, max width) and shared components such as buttons and the skip link.
view_homepage.tpl Homepage template served at the bare Launchpad URL, with its own inline styles and script.
lp_*.html One file per page: Impact, Find a Site, Form Library, Team, Leadership and so on.
multigrid.js Builds the My Requests grid by merging records from several LEAF sites (see SOURCE_SITES).

How pages load

Every page gets the universal header. Only the homepage (view_homepage.tpl) also runs the router, which swaps content in place so the header and breadcrumb stay put.

  1. main.tpl loads leaf_header.css and leaf_header.js and hides LEAF's native header and footer.
  2. The header script mounts the nav and breadcrumb. It matches the current URL against its route list to build the breadcrumb. The homepage and unknown pages show none.
  3. On the homepage, a nav click sets a hash such as #find_site instead of navigating.
  4. loadView() fetches the route's URL, removes LEAF chrome, extracts #content and places it in #lpSwapHost.
  5. Scripts matching SCRIPT_BLOCKLIST (the header itself and legacy nav scripts) are not run again.
  6. A route marked iframe: true is mounted in an iframe instead. Use this for a full separate LEAF app, such as the Help Library.
  7. Back and forward use hash history. Each view change is announced through #lp-live-region.

Hash keys come from the ?a= value, lowercased. HREF_HASH_KEY_OVERRIDES drops the lp_ prefix, and LEGACY_HASH_KEY_ALIASES keeps old #lp_* links working.

In-page anchors inside a loaded page are handled by the router, so a link such as href="#ldc-files" scrolls without changing the route.

Chrome suppression

A fetched LEAF page arrives with its own header, footer and skip links. suppressChrome() in leaf_header.js removes anything matching CHROME_SELECTORS before the router shows the page, so the shell's header is the only one on screen. It also drops the shell's own elements, such as #lpSwapHost and .lp-header, so a fetched Launchpad page can't bring in a second copy.

extractContent() then picks what to show, using the first match in this order:

  1. [data-lp-content], an explicit opt-in
  2. #content
  3. #bodyarea
  4. <main>
  5. the whole <body>, as a last resort

Two common fixes:

  • A fetched page shows a stray header, footer or skip link: add its selector to CHROME_SELECTORS.
  • A page loads more than you want: put data-lp-content on the wrapper you do want. It wins over every other rule.

The code is in the Chrome suppression snippet under Components.

Add a page

  1. Create lp_<name>.html. Link ./files/launchpad.css in the head and put the content inside <div class="lp" id="lp-root"> and <main id="lp-main" tabindex="-1">. Do not add a nav or skip link; the header adds them.
  2. Publish it as report.php?a=lp_<name>.
  3. Register the route in leaf_header.js. Public pages go in NAV_SECTIONS, or in SUBROUTES if nested under another page. Internal pages get an INTERNAL_*_ROUTE constant, as shown below.
  4. Add the page to HREF_HASH_KEY_OVERRIDES to set its short hash key.
  5. Link to it with a root-relative path such as /launchpad/report.php?a=lp_<name>.

Sysadmin access

Two checks work together, and only the first protects content.

Page gate (server side)

Sysadmin pages wrap their content in a Smarty condition on group 1. Anyone else is served the access-restricted block and never receives the page content.

Nav flag (client side)

leaf_header.js reads data-is-sysadmin from its own script tag to show or hide the Internal nav. Anything other than 1, true or yes keeps it hidden. This only controls what appears in the nav, so never use it to protect data.

Header script attributes

  • data-is-sysadmin shows or hides the Internal nav.
  • data-csrf-token is the LEAF session token the Feedback button sends with its writes. Without it the button renders but submissions fail with an inline error.

Both are filled by Smarty in main.tpl. A page that loads the header script on its own must set them too.

Multigrid (My Requests)

multigrid.js shows a person's records from several LEAF sites in one sortable table. It is embedded once in view_homepage.tpl and opened by the View My Requests button.

How it works

  • data-user-id carries the signed-in user's ID from Smarty, because Smarty tags don't render inside a .js file. The script strips the comment markers the platform leaves around the value.
  • On load it queries every entry in SOURCE_SITES at the same time for records that belong to that user and aren't deleted, in batches of up to 500.
  • Each source loads or fails on its own, so one slow or failing site doesn't block the others.
  • TABS decides what the person sees. A single tab shows one source, a merged tab combines several, and all shows every source with a Site column.
  • Record IDs repeat across LEAF sites, so each row is keyed by site URL plus record ID, and the Request column sorts by title instead of ID.
  • Every tab is drawn by one function, renderDataTable(), with a column set per layout: generic, Site Creations and All Requests.
  • Each Request links to the record's print view on its own site.

Keep the file ASCII-only. Non-ASCII characters have been corrupted by deploy pipelines before, which silently breaks strings and comments.

Add a source

  1. Add the site to SOURCE_SITES.
  2. Add its key to the sourceKeys of the All Requests tab, and either give it its own tab or add it to an existing merged tab.
  3. If it needs custom fields or a filter, add a branch in myRecordsQuery().
  4. If its Status comes from a custom field, add a branch in statusTextForSource(). Sources without one share lastStatus.
  5. Open View My Requests with an account that has records on the new site and check that its rows, links and status appear.

Embed tag

Place once in the template, anywhere in the body. data-trigger turns it into a modal opened by that button; without it the grid mounts inline in data-mount.

Add a source

One entry per LEAF site, in SOURCE_SITES. The url needs its trailing slash.

Add or extend a tab

Tab order here is the display order. Use kind "single" for one source, "merged" for several in one table, and "all" for every source.

Custom fields and filters

In myRecordsQuery(). getData lists the indicator IDs to fetch, and terms narrows the records.

Custom status

In statusTextForSource(). Without a branch, a source uses the shared lastStatus value.

Nav badges

A badge is a small pill next to a menu item's title. It tells people a destination isn't fully live. Set it with the badge field on an item in NAV_SECTIONS, and the text is shown as typed.

  • Coming Soon is used for pages that exist but are still in development, such as Use Cases and Learn. It is a neutral gray pill with a contrast ratio of 8.48:1.
  • Add a badge by adding the badge line to the item.
  • Remove it by deleting that line when the page goes live. Nothing else changes.
  • To keep an item out of the menu entirely, use hidden: true instead of a badge.
  • Beta is a gold variant that is not live yet. It needs the three edits in the Beta badge snippet: a badgeClass field, a small change to linkRowHTML(), and one CSS rule.

The snippets are under Components: Nav badge, Add or remove a badge, and Beta badge (pending patch).

Coming-soon pages

lp_use_case and lp_learn were built as placeholders so the page can be linked, shared and reviewed before the real content exists. They share one pattern:

  • A hero with a round icon, a Coming Soon eyebrow, the page title, a short description and an In development pill.
  • A What to Expect section listing what the finished page will include.
  • Optionally, something useful in the meantime. Learn adds an In the meantime band whose button opens a live training registration modal.

Create one

  1. Copy lp_use_case.html to lp_<name>.html. Change the icon, text and the id values that tie headings to sections.
  2. Publish it as report.php?a=lp_<name>.
  3. Register the route, following the steps in Add a page, and give the nav item badge: "Coming Soon".
  4. When the page is ready, replace the two sections with the real content and delete the badge line.

The Coming-soon page and In the meantime band snippets are under Components.

Redirects

When these pages moved into the Launchpad, each old page was given a one-line script that sends visitors to the new address. Place the script on the old page. It uses window.location.replace(), so the old address isn't kept in history and the back button doesn't bounce people forward again.

Build standards

Paths and dependencies

  • Use relative paths. Use a full URL only to point at another LEAF site.
  • Host everything locally. Anything inside the LEAF platform, such as fonts under /app/libs/css/fonts/ or DOMPurify under /app/libs/js/dompurify/, counts as local.

Icons

  • Icons are inline SVG from Material Symbols (Filled), using viewBox="0 -960 960 960" and fill="currentColor". No icon font is loaded.
  • Reuse an icon already in ICON_SVG (header) or the page's own icon map before adding a new one. For a new one, download the SVG by its Material Symbols name and add its path.
  • Decorative icons get aria-hidden="true".

Accessibility and responsive checks

  • Meet WCAG 2.1 AA and Section 508: one h1, headings in order, visible focus, 44px touch targets, and contrast of at least 4.5:1 for text.
  • Give tables a caption and scope on headers. Wrap wide tables and code in a keyboard-focusable scroll region.
  • Respect prefers-reduced-motion.
  • Test at about 360px wide and at desktop width. Nothing should scroll sideways except a wrapped table or code block.

Code style

  • Match the surrounding code. Use the same class prefixes, tokens and spacing as sibling pages.

Appendix: Ideas and Help Library

Submit an Idea and Help Library appear inside the Launchpad, but they are separate LEAF sites. The Launchpad fetches them and shows them in its own frame, so their content and behavior are changed at their own root, not here.

Where to change each part
What Where
Ideas page content and scripts /platform/ideas/
Idea votes and Help Library article feedback Saved in /platform/votes
Help Library articles and layout /platform/help_library/
Menu entry, route and hash key leaf_header.js

Submit an Idea

  • The nav item points at https://leaf.va.gov/platform/ideas/. It is fetched, stripped of its own header and footer, and its content is placed in the Launchpad page, with no iframe.
  • The router adds a <base> for the Ideas folder, so its relative calls such as ./api/form/query go to the Ideas site and not the Launchpad.
  • Its scripts run again inside the Launchpad. Scripts that wait for page load are held and started after the content is in place.
  • Votes are saved in /platform/votes, not in the Launchpad.
  • My Requests also reads the Ideas site. See Multigrid.

Help Library

  • The route uses iframe: true and fixedHeight: true. Help Library has its own internal routing, so it needs its own window. The frame fills the screen below the header and scrolls inside itself.
  • The frame stays hidden behind a spinner until it finishes loading, so its own header never flashes.
  • Each time someone opens an article, Help Library posts the article ID to the Launchpad. The Launchpad accepts it only from https://leaf.va.gov and writes it into the address as #help_library-article-<id>.
  • Opening a link with that hash jumps straight to the article.
  • Article feedback is saved in /platform/votes, the same place as Idea votes, and not in the Launchpad.
  • Articles and layout are edited at /platform/help_library/. Changing the article-opening code there can break deep links, since the Launchpad expects that message.
