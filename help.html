LEAF Project Dashboard — Help & Reference

A quick reference for everything you'll see and use on the Project Dashboard.

1. Getting Started

The Project Dashboard is the internal project management hub for tracking Projects, Tasks, Objectives & Key Results (OKRs), and overall team activity. It brings together table, Kanban, and Gantt views alongside an Analytics tab for at-a-glance reporting.

You'll access it the same way as any other LEAF programmer page — through your team's Launchpad link or a direct dashboard URL provided by your LEAF point of contact.

Replaying the tour

Look for the circular Help button (a "?" icon) near the top of the page. Clicking it any time relaunches the same step-by-step walkthrough — handy if you want a refresher or you're showing a teammate around.

visibility

You'll see this when…

…a dimmed overlay appears with a highlighted spotlight box and a small tooltip card — use Next / Back to move between steps, or Skip / Esc to exit.

2. The Add Menu

The + Add button opens a dropdown menu for creating new records without leaving the dashboard. Each option opens the matching LEAF form so you can fill in details and submit.

+ Project

Starts a new Project record. Use this for any new body of work that will have its own tasks, timeline, and (optionally) a Customer Project Hub.

+ Task

Starts a new Task record. Tasks can be linked to a Project, assigned to a teammate, and tracked through the Table, Kanban, or Gantt views.

+ Recurring Task

Sets up a task that repeats on its own. You configure it once, and the next copy is auto-generated whenever the current one is marked complete — no manual re-entry needed.

lightbulb

Tip

Recurring tasks display a small change_circle icon next to the title so you can spot them at a glance in the table and on Kanban cards.

+ Objective

Starts a new Objective record — the higher-level goal that Key Results and the Projects/Tasks tied to them roll up into.

+ Key Result

Starts a new Key Result record under an Objective. Key Results are the measurable outcomes that Projects and Tasks count against (see OKRs below).

3. Filters & Activity

The filter row above each table lets you narrow down what's shown using multi-select dropdowns. Click a filter to open its checklist, select one or more values, and the table updates immediately.

Available filters

You can filter by Project, Status, Assigned To, Category, and Priority. Each one supports multiple selections at once, so you can, for example, view only High and Medium priority tasks assigned to two specific people.

Activity date range

The Last 7 / 14 / 30 days buttons scope activity-based views to a recent window. Use these when you want a quick pulse on what's changed recently rather than the full history.

Clearing filters

A Clear button resets all active filters back to their defaults in one click, returning the table to its unfiltered state.

warning

Watch out

Filter selections persist across sessions — they're remembered the next time you open the dashboard. If a view looks emptier or different than expected, check the filter row first and hit Clear.

4. Views — Tasks Tab

The Tasks tab offers three ways to look at the same underlying data: Table, Kanban, and Gantt. Switch between them using the view toggle near the top of the tab — your filters carry over automatically.

Table view

A sortable, scrollable table of every task matching your current filters. Click a column header to sort by that column; click again to reverse the order.

Kanban

Tasks appear as cards grouped into status columns. Drag a card to a different column to update its status — the change saves automatically.

visibility

You'll see this when…

…you can't use a mouse: focus a card and use Shift + arrow keys to move it between columns instead of dragging.

When a card moves into a completed status, its completion date is stamped automatically — there's nothing extra to fill in.

Gantt

Each row shows a task's name and dates, with a horizontal bar representing its timeline. Bar color reflects priority — red for High, yellow for Medium, blue for Low, and gray when no priority is set.

5. Inline Editing

Many table columns can be edited right from the dashboard — no need to open the full LEAF record. Look for the edit pencil icon in a column header: only those columns are editable. Columns without the pencil are intentionally locked due to the nature of the content.

Click any cell in an editable column to open its inline editor in place.

warning

Save & Cancel keys — read this first

Enter saves your change. Esc cancels and discards it. For multi-line fields, use Shift + Enter to add a new line — plain Enter in a multi-line field will not save; it just adds a line break.

Inline changes write directly to the LEAF record for that field — there's no separate "draft" state. Once saved, the record is updated immediately.

warning

Watch out — dropdown limitation

If a dropdown option has never been selected before (for example, a new fiscal year like "FY30"), it won't appear in the inline dropdown's choices yet.

Workaround: open the LEAF record directly and select the new option there once. After that, it'll appear in the inline dropdown going forward.

Red workflow warning icon

visibility

You'll see this when…

warning …a red warning icon appears in the Status column when a record's status is marked Complete or Cancelled, but the underlying LEAF workflow is still open. This needs to be resolved in the workflow itself — updating the status here alone won't close it out.

6. Inside a Project

Every Project follows one of two workflows depending on its type. Knowing which one applies tells you what steps to expect.

A. National / Managed Services Workflow

Route: Project Phases 1–5 → Project Closure/Documentation → PO Review.

The five phases progressively build out the Customer Project Hub — a read-only, customer-facing status page for the project.

visibility

You'll see this when…

language …a globe icon appears next to a project's name in the Projects table — it means a Customer Project Hub has been created for that project. Click it to open the Hub in a new tab.

To fill out the content shown on the Hub page, use the internal use forms attached to the Project record — that's where Hub-facing details are entered.

B. All Other Projects Workflow

Route: Start Project → Project Closure/Documentation → PO Review.

There's no phase progression for these projects — they move straight from kickoff to closure without the five-phase Hub-building process.

C. Project View Modal

Click anywhere on a project's row in the Projects table to open its view modal, which lists every task currently assigned to that project.

The + Task button inside the modal automatically captures the project for you — there's no need to manually select it in the new task's form.

D. % Complete Column

This column is auto-calculated from the completed tasks assigned to the project — you don't set it manually.

When every assigned task is done, the column reaches 100% and the project's status automatically updates to Completed.

lightbulb

Best practice

Add all known tasks to a project up front — even ones you haven't started — so the % Complete figure reflects real progress instead of an inflated percentage based on a partial task list.

E. Notes & Attachments

Both Project and Task LEAF forms include an internal use form for Notes & Attachments. Use it to store files, context notes, and running updates tied to that specific record — a good place for anything that doesn't belong in a dashboard-facing field.

7. Analytics Tab

The Analytics tab turns your Projects, Tasks, and OKR data into charts so you can spot trends, overdue items, and overall health without digging through tables row by row.

What the charts show

You'll find charts covering things like task status breakdowns, project health at a glance, overdue tasks, and OKR progress. Click into a chart where available to drill down into the underlying records.

Year / Quarter filters

Use the year and quarter controls above the charts to scope the data to a specific period — useful for quarterly reviews or year-over-year comparisons.

Ticket Transfers chart

At the bottom of the Analytics tab, the Ticket Transfers chart tracks the volume of tickets imported from other team sites over time. This is the same activity described in Transfers below.

8. OKRs (Objectives & Key Results)

Objectives are the high-level goals your team is working toward. Key Results are the specific, measurable outcomes that show whether an Objective is being met. Projects and Tasks can be linked to a Key Result so their progress rolls up into the OKR.

warning

Common gotcha

For a task or project to count toward an OKR, both the Objective field and the Key Result field must be selected on its form. Selecting only the Objective is not enough — without a Key Result selected, the work isn't counting against anything, even though it may look linked at a glance.

9. Transfers (UX / Support → Dashboard)

Transfers bring tickets from the UX or Support sites into this dashboard as a new Task or Project, so cross-team work can be tracked in one place.

lightbulb

Note

The Ideas tab isn't part of this yet — Ideas-site transfers aren't live.

Ticket column

If a number appears in the Ticket column, that record was imported from another team site rather than created directly in the dashboard.

visibility

You'll see this when…

…hovering over the ticket chip shows which site it came from. Chips are color-coded by source: Support chips are blue, and UX chips are amber/orange.

Click the ticket number itself to open the original ticket on its source site for full detail.

Tracking transfer volume

The total volume of transferred tickets over time is trackable in the Analytics tab, in the Ticket Transfers chart at the bottom of the page.

10. Tips & Gotchas

A quick-reference recap of the things people most often ask about.

  • warning

    Red workflow warning icon

    Status says Complete or Cancelled, but the LEAF workflow is still open. Resolve it in the workflow — see Inline Editing.

  • change_circle

    Recurring tasks

    Don't manually re-create them. The system auto-generates the next copy as soon as the current one is marked complete — see The Add Menu.

  • keyboard

    Inline editing save keys

    Enter saves, Esc cancels, and Shift + Enter adds a new line in multi-line fields — see Inline Editing.

  • lock

    Inline dropdown limitation

    If an option isn't listed yet, select it directly in the LEAF record first — then it'll appear inline going forward.

  • save

    Filters persist across sessions

    If your view looks unexpected when you return, check the filter row and clear it — see Filters & Activity.
